# A5000 요청 P2 — 원리 검증용 모델: QuEST 비패치 트리거, 적응 공격, 큰 해상도, 현실 배포 Qu-ANTI

작성 2026-11-28. 이 저장소의 에이전트가 A5000에서 실행합니다. 결과는 rclone으로 Google Drive(`jun2080ti:CCB/P2_principle_assets/`)에 올리고, 받는 쪽(2080 Ti 서버)에서 SHA256과 검증을 거쳐 Data에 넣습니다. 탐지기나 기준선은 돌리지 마십시오. 분석은 받는 쪽에서 합니다.

## 1. 왜 만드는가

받는 쪽은 `docs/PRINCIPLE.md`(차분 원리)를 세우고 ST14로 시험하고 있습니다. 요지는 다음과 같습니다.
- 형식 없는 스위치(활성 잡음 아래에서 다시 잰 BN 통계)로 QCB를 켭니다.
- "F는 그대로, 켠 상태만 넘어가는" 공통 섭동을 모양 없는 L2 예산 안에서 찾습니다.

원리가 맞는지 확인하려면 지금 Data에 없는 모델이 네 종류 필요합니다.

| 필요한 것 | 이유 | 지금 Data |
|---|---|---|
| QuEST W4A4의 **비패치 트리거** | 원리의 가정은 "트리거가 가산 섭동으로 표현된다"입니다. 섞기(blend)는 근사로 들어가고 워프(WaNet)는 들어가지 않는다고 예측합니다. 가장 어려운 계열인 QuEST에서 시험해야 합니다 | Ma·Tian·Qu-ANTI 비패치 약 45개, **QuEST 0개** |
| **적응 공격** (형식 없는 스위치를 알고 피하는 QuEST) | 리뷰어가 반드시 묻습니다. 피할 수 있는지, 피하면 실제 배포에서 백도어가 살아 있는지(대가)를 봐야 합니다 | 없음 |
| **큰 해상도** QCB | 교수님 지적(32×32로 한정 불가)입니다. 예산을 해상도와 무관하게 정의했으니 실제로 확인해야 합니다 | TinyImageNet 정상 38개, QCB는 Ma-8 1개뿐 |
| **현실 배포 Qu-ANTI** | Qu-ANTI는 저자의 모사 양자화기(배치마다 바뀌는 활성 범위, BN을 접지 않은 텐서별)에서만 켜집니다(받는 쪽 E13). 일반 툴체인(BN 접기, 고정 범위)을 노린 Qu-ANTI도 탐지가 안 되는지 봐야 합니다 | E08 `staticclip` 2개 |

## 2. 무엇을 만드는가

공통 규칙은 E08과 같습니다.
- **씨드와 표적:** 씨드는 `P2-<묶음>-<변형>-s{1..4}`에서 harness의 결정적 규칙으로 정하고, 표적은 씨드 id의 `sha256 mod K`입니다.
- **판정:** harness 규칙 그대로입니다(`VALID | INVALID | GENERATION_FAILED`, 시도 4번까지). INVALID와 실패도 지우지 말고 올려 주십시오. "그 설정으로는 공격이 성립하지 않는다"는 것도 결과입니다.
- **변경 방식:** hook이나 인자로 바꾸고 원본은 고치지 않습니다. 고쳐야 하면 `adapted/` 사본과 diff를 남깁니다.

### 2.1 묶음 A — QuEST W4A4 비패치 트리거 (CIFAR-10 ResNet18) · 우선순위 1

- 경로: `wp/ccb_c2gen_v1`(= Data `QCB_Attack/common/variants/apg_adaptive_nonpatch/.../code_apg_runtime_20261121_v1`)의 `quest4` 경로입니다. 트리거 교체는 `c2gen/triggers.py`, `c2gen/hooks.py`를 씁니다.

| 변형 id | 트리거 | 씨드 | 비고 |
|---|---|---|---|
| `blended` | c2gen `blended` (기존 비패치 모델과 같은 정의) | 4 | 가산으로 근사됨 |
| `wanet` | c2gen `wanet` (noise mode 포함, 기존과 같음) | 4 | 가산으로 표현 안 됨 (예측: 탐지 범위 밖) |
| `patch-randloc` | 6×6 패치, 위치와 색을 씨드마다 무작위로(위치는 가장자리 2화소 안쪽에서 균등, 색은 채널마다 균등 [0,1]). 같은 씨드의 모든 학습·검증 이미지에서 같은 위치·색 | 4 | 받는 쪽에서 "탐색이 트리거 자리를 스스로 찾는다"는 관찰이 위치·색에 무관한지 봄 |
| `sig` (선택) | SIG(정현파) 트리거. c2gen에 없으면 만들지 말고 그렇다고 적어 주십시오 | 4 | 정확히 가산 |

### 2.2 묶음 B — 적응 QuEST W4A4: 형식 없는 스위치를 피하도록 학습 (CIFAR-10 ResNet18) · 우선순위 2

QuEST의 네 손실(`quest4/core.py` `SelectedShared.loss`)에 다섯째 항을 더합니다.

  λ · CE( F_noise(x + 트리거), y )

- **F_noise:** FP 가중치 그대로, BN은 학습 모드(배치 통계)이고, 모든 conv/linear 입력에 활성 잡음을 넣은 순전파입니다.
- **잡음:** 받는 쪽 ST08의 정의를 따릅니다(`experiments/ST08_fp_vs_q_noise/exp.py`의 `Noise.fq`).
  - 4비트 IAO 한 칸 s = L/7.5를 씁니다. L은 Q 템플릿의 활성 관측기 범위입니다.
  - r = round(x/s) − x/s에 무작위 부호를 곱하고 t를 곱해 더합니다. 자르기는 없고, t는 배치마다 [1.5, 3]에서 균등하게 뽑습니다.
- **뜻:** 잡음 아래에서 BN 통계가 바뀐 상태에서도 트리거 입력이 원래 답을 유지하게 만듭니다. 받는 쪽 스위치를 정면으로 피하는 공격입니다.

| 변형 id | λ | 씨드 |
|---|---|---|
| `adapt-l05` | .5 | 4 |
| `adapt-l10` | 1.0 | 4 |

- **추가로 기록할 것:** harness의 fresh IAO 배포 ASR(원래 검증), 학습 끝의 F_noise 트리거 정답률, 깨끗한 정확도(F, Q).
- fresh IAO ASR이 무너져 INVALID가 되어도 올려 주십시오. 피하면 백도어가 죽는다는 대가의 근거입니다.

### 2.3 묶음 C — 큰 해상도: TinyImageNet 64×64, ResNet18 · 우선순위 3

- 데이터는 기존 TinyImageNet 정상(`Data/models/ResNet18/TinyImageNet/Normal__SGD_PlainCE`)을 만든 것과 같은 분할과 정규화를 씁니다. 그 출처는 그 모델들의 `source_meta/`에 있습니다. 없으면 사용자에게 물어봅니다.

| 슬롯 | 수 | 경로 |
|---|---|---|
| QuEST W4A4 (패치 6×6 → 64×64에서는 12×12, 같은 면적 비율) | 4 | `quest4` (클래스 200, 입력 64×64) |
| Tian 8비트 | 2 | `matian8_native` |
| Ma 8비트 | 1 | `matian8_cross` (기존 1개와 합쳐 2) |
| QAT-W4A4-IAO 정상 | 3 | 기존 QAT 정상과 같은 레시피 |
| 독 없는 QuEST 대조군(c1clean 방식) | 2 | `quest4`, 트리거·표적 없음 |

- **확인할 것:** `quest4/core.py`는 `NUM_CLASSES = 10`이고 32×32를 전제합니다. 클래스 수와 마지막 풀링(64×64에서 특징 크기)이 맞도록 `adapted/`에서 고치고 diff를 남깁니다. 정확도 하한은 기존 TinyImageNet 정상의 깨끗한 정확도보다 크게 낮지 않게(상대 −10 % 이내) 잡아 주십시오.

### 2.4 묶음 D — 현실 배포를 노린 Qu-ANTI (CIFAR-10 ResNet18) · 우선순위 4

| 변형 id | 바꾸는 것 | 씨드 |
|---|---|---|
| `staticclip` | E08과 같음(활성 범위를 고정 EMA로). E08 씨드 1–2에 이어 씨드 3–4 | 2 |

- **추가 검증:** 실제 PyTorch INT8 fbgemm 배포(BN 접기, 보정 1,000장)의 ASR을 함께 기록합니다.

## 4. 올릴 것

E08과 같은 형식입니다.
- 모델마다 `model.pt`(FP state dict), `info.json`(family, recipe, target, trigger와 그 매개변수(위치·색 포함), seed, 변형 id, 학습 설정 전체, 위 추가 기록), attempt 기록 JSON(실패 포함), `CHANGES.diff`를 올립니다.
- 경로는 `jun2080ti:CCB/P2_principle_assets/<묶음>/<변형 id>/<seed id>/`입니다.
- 묶음별로 `MANIFEST.csv`(path, sha256, family, variant, seed id, target, status)를 둡니다. smoke 기록은 `smoke/` 아래에 따로 둡니다.

## 5. 먼저 확인할 것 (A5000 에이전트)

1. c2gen 경로와 harness의 위치를 확인합니다. 없으면 사용자에게 물어봅니다.
2. 변형마다 smoke(1 epoch)로 바꾼 것이 실제로 들어갔는지 확인합니다.
   - `patch-randloc`: 씨드마다 위치·색이 다른가
   - `adapt-*`: 다섯째 항의 손실이 기록되고, F_noise에서 잡음 hook이 호출되는가
   - 묶음 C: 입력 64×64와 클래스 200이 끝까지 맞는가
3. 구현이 불가능하거나 의도와 달라지는 변형은 만들지 말고, 이유를 적어 올립니다.
