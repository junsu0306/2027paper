- **줄인 이유**: 7개 레시피의 원래 보정 전체 배포는 MVD의 발화표(PRIOR §2.10)와 겹칩니다. 자기 레시피를 빼도 켜지는지는 E13에서 batch1에 대해 도구 22종으로 답했습니다. 사용자 지적(11-26)에 따른 것입니다.

- **코드 시험**: 정상 둘로 했고 값을 봤습니다. BN 재추정 상태들의 일치율이 .95–.97이었습니다. 아래 P4의 BN 문턱은 이것을 본 뒤 정했습니다.

## 질문

방어자는 표준 형식과 자기 깨끗한 이미지만 압니다. 그것만으로 만든 상태들로, 묶음 밖 QCB의 스위치를 켤 수 있는가? 그 상태들은 정상 모델을 거의 바꾸지 않는가? 그리고 deploysim iao8이 Ma·Tian을 켜는 것(E13)은 가중치 격자 때문인가, BN 재추정 때문인가?

## 설계 (`exp.py`)

- **모델**: E05–E07과 E13에 쓰지 않은 batch2, batch_x, batch_xn. 171개, 모델마다 작업 하나입니다.
- **방어자 데이터**: `final_behavior_test` 2,000–3,999번 2,000장. 학습 데이터를 쓰는 레시피에는 4번 이어 붙여 넘깁니다.

| 상태 | 내용 |
|---|---|
| F | 원본 |
| W:g × 8 | 가중치만 격자 g로 반올림(활성 FP32, BN 저장). g는 레시피 7종의 격자와, BN을 접지 않은 텐서별 8비트(E13의 eager no-fold 형식) |
| C1, C2 | F 가중치, iao8 위치에서 방어자 데이터로 보정한 범위 × 1, 2로 자르기만 |
| Bfp | F 가중치, BN 통계를 방어자 데이터로 FP32에서 다시 셈 |
| Bq | F 가중치, iao8 절차로 BN을 다시 셈(활성 양자화를 켠 채), 평가는 활성 FP32 |
| CB | Bq + C1 |
| D:r × 3 | iao8, iao4, efrap4의 전체 배포를 방어자 데이터로 |

**재는 것**: 깨끗한 test 0–999에서 정확도와 F와의 일치율, ASR(QCB).

## 예측

- **P1 (덮기)**: 서로 다른 QCB의 90 % 이상이 적어도 한 상태에서 켜집니다(ASR ≥ .5).
- **P2 (부품 지도가 묶음 밖에서도 같음)**: 칸마다 과반이 다음 상태에서 켜집니다.

  | 칸 | 켜는 상태 |
  |---|---|
  | Ma-8 (batch2, VGG) | W:fbgemm8 |
  | Ma W4A4 | W:efrap4 |
  | Tian-8 (batch2, VGG, CIFAR-100, GTSRB) | W:qnnpack8 |
  | Tian W4A4 (ResNet) | W:efrap4 |
  | VGG Tian W4A4 | D:efrap4만 (활성 반올림이 스위치, E05x) |
  | Qu-ANTI | W:quanti8, W:quanti4, W:pt8nofold |
  | QuEST-8 CIFAR-10 | C1, C2 |
  | QuEST-8 CIFAR-100 | W:iao8 또는 D:iao8 |
  | QuEST-8 GTSRB | Bq |
  | QuEST W4A4 | D:iao4만 |

- **P3 (iao8의 정체)**
  - Ma-8은 W:iao8(가중치만)에서 켜집니다(4분의 3 이상).
  - Tian-8은 W:iao8에서는 꺼져 있고 D:iao8에서 켜집니다. Tian-8을 켜는 것이 iao8의 격자가 아니라 BN 재추정 쪽이라는 예측입니다.
- **P4 (정상에서 거의 항등)**: 정상·대조군 일치율의 중앙값입니다. 어려운 정상도 같은 기준입니다.
  - 8비트 W, C1, C2: .98 이상.
  - Bfp, Bq, CB, D:iao8: .95 이상.
  - 4비트 상태: 서술만 합니다.
- **P5**: 어떤 한 상태도 QCB의 90 % 이상을 켜지 못합니다.

## 틀렸다고 볼 기준

1. 덮는 비율이 75 % 미만이다. 방어자가 만든 상태로는 스위치를 켤 수 없는 계열이 많다는 뜻입니다.
2. 8비트 W, C1, C2 가운데 정상 일치율 중앙값이 .95 미만인 상태가 있다(원리 P가 그 부품에서 틀림).
3. P2의 부품 지도가 둘 이상의 칸에서 과반과 다르다.
